# NabyScape Rust Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native Rust `nabyscape.exe` with every NabyScape 2.24.0 feature, reading the same user data, at a fraction of the WPF build's memory.

**Architecture:** Four crates under `rust/`: `naby-core` (platform-free logic), `naby-render` (tiny-skia + fontdue painter and immediate-mode widgets), `naby-ui` (all views, platform-free, snapshot-tested), `naby-win` (Win32/WinRT/WASAPI host). Views read snapshot structs and emit `Command`s; only `naby-win` touches the OS.

**Tech Stack:** Rust 2021 (toolchain 1.97), `windows` 0.61, tiny-skia 0.11, fontdue 0.9, serde/serde_json, chrono, ureq 2 (blocking), png, zune-jpeg.

**Spec:** `docs/superpowers/specs/2026-10-29-rust-port-design.md` plus the C# sources each task names (they are the behavioral spec) and their tests in `src/NabyScape/Tests`.

## Global Constraints

- Plan and planning reviews: Opus. Task implementation subagents: Sonnet.
- Never modify anything outside `rust/` and `docs/superpowers/` (the C# tree stays as the reference).
- Same data folder and files: `naby_core::paths::data_dir()` = `%LOCALAPPDATA%\NabyScape`; JSON keys PascalCase exactly as C# `System.Text.Json` writes them; unknown keys are preserved on save (`#[serde(flatten)] extra: serde_json::Map<String, Value>`).
- No async runtime (no tokio/async-std), no GPU API, no webview, no .NET. Background work: `std::thread` + channels; HTTP: `naby_core::http::agent()`.
- No timer runs while nothing animates or counts down. Pixel buffers of hidden surfaces are dropped. Caches are byte-bounded.
- `unsafe` only in `naby-win`, each block with a `// SAFETY:` line.
- Port the C# tests that cover a ported file into Rust `#[cfg(test)]` modules (same scenarios and expected values). UI-only C# diagnostics (`src/NabyScape/Diagnostics`) are not ported; their assertions become snapshot or state tests where they check behavior.
- Every task passes, from `rust/`: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo clippy -p naby-win --target x86_64-pc-windows-gnu -- -D warnings`.
- Shared types already in the scaffold, do not redefine: `naby_core::color::Rgba`, `naby_core::paths::{data_dir, legacy_data_dir, local_app_data}`, `naby_core::http::{agent, USER_AGENT}`, `naby_core::command::Command` (extend by adding variants only).
- Module ownership: a task edits only the files it lists plus `Cargo.toml` dependency lines it needs; a module file `x.rs` may become `x/mod.rs` with submodules.
- Commit messages: `rust: <what>`; one commit per task (more is fine), never push from a subagent.

## Review Focus

- A `settings.json` written by C# 2.24 (including keys this port does not model) loads, normalizes, and saves back without losing keys → test in Task 2.
- Corrupt, truncated, empty, oversized (>32 MiB) or future-schema documents never crash and never get overwritten silently → tests in Task 3.
- Offline / HTTP 4xx-5xx / slow responses for lyrics, weather, updates and assistant providers resolve to an "unavailable" state, never a panic or a stuck spinner → tests in Tasks 5, 6, 8 using an injected fetch closure.
- No media session, no audio endpoint, no battery, no network adapter: every snapshot has an `Unavailable` form and every view paints it → tests in Tasks 5, 6, 12, 13.
- Monitor unplug / DPI change / taskbar on any edge while the dock is shown: geometry recomputes from the new monitor work area → tests in Task 7 (pure geometry) and manual check in Task 11.

## Wave 5

### Task 16: Voice

- Port: `Features/Assistant/{AssistantVoiceSession.cs, AssistantVoiceAudio.cs, AssistantVoiceOverlay.cs, AssistantVoiceView.cs, AssistantVoiceWorkspace.cs, AssistantWakeRuntime.cs, AssistantWakeWord.cs, AssistantModernSpeech.cs, AssistantLocalVoice.cs, AssistantManagedSpeech.cs, AssistantSpeechInstall.cs, AssistantSpeechNative.cs, AssistantSpeechPlatform.cs, AssistantSpeechRemoval*.cs, AssistantSpeechSetup.cs, AssistantSpeechWorker.cs, AssistantOwnSpeech.cs}`, `tools/local_voice_server.py` (embedded as before).
- Create: `naby-win/src/voice/{mod.rs, capture.rs, playback.rs, wake.rs (Windows.Media.SpeechRecognition), realtime.rs, local.rs, install.rs}`, `naby-ui/src/assistant/voice.rs`. Speech models load only while voice is active and unload after.
- **Default listening model: Cactus Compute Whistle (user decision, 2026-10-29).** One 16.9 MB `whistle.cact` (HF `Cactus-Compute/whistle`, weights-only, engine version 2.0.0) run by the Cactus Needle engine `libneedle.dll` (HF `Cactus-Compute/needle3` platform folders `windows-x86_64` / `windows-arm64`, engine 3.3.3; Apache-2.0 per the needle repo). Both ship inside the installer/portable ZIP next to `nabyscape.exe` (no first-run download), with SHA-256 pinned in `rust/whistle.lock` and verified at load. `naby-win/src/voice/whistle.rs` loads the DLL with `LoadLibraryW` only while voice is active and unloads it after (`FreeLibrary`); C API (from `needle/agent/whistle.py`):
  - `int needle_load(const char* data, uint64_t len)` (whole `.cact` bytes; <0 = error)
  - `int needle_transcribe(const float* samples, int count, const char* language /*NULL=auto*/, const char* keywords /*\n-separated or NULL*/, int word_timestamps, char* out, int out_len)` → JSON `{text, language, ttft_ms, decode_tps[, words]}`
  - `int needle_stream_transcribe_process(const float*, int, const char* language, const char* keywords, char* out, int out_len)` / `int needle_stream_transcribe_stop(char* out, int out_len)` → JSON with confirmed/pending words
  - `const char* needle_last_error(void)`
  - Input 16 kHz mono f32 in [-1,1]; one model per process, not thread-safe (single worker thread).
- Whistle languages: en, de, fr, es, it, nl, pl (auto-detect). For other languages (e.g. the app's Indonesian UI) the existing optional speech packs / providers stay available as alternatives. Whistle is speech-to-text only: TTS keeps the existing options. Wake word stays on Windows speech recognition so an always-on Whistle loop never runs.
- `rust/build-release.ps1` (Task 17) downloads `whistle.cact` + `libneedle.dll` for the target arch, checks them against `rust/whistle.lock`, and packages them.
